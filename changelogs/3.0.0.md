First release of **ChestTracker Reloaded**, an unofficial fork of
[Chest Tracker](https://github.com/JackFred2/ChestTracker) by JackFred, updated for **Minecraft 26.2**.
Not affiliated with or endorsed by JackFred. If the original updates to 26.x, use it instead.

In game the mod is still called **Chest Tracker**.

## Requirements

- Minecraft **26.2**, Fabric, **Java 25**
- Fabric API, YACL ≥ 3.9.0

## ⚠️ Before installing

- **Remove Where Is It.** Its search and in-world highlighting are now built in, and running both
  will conflict. This is enforced with a `breaks` declaration.
- **Remove the original Chest Tracker** for the same reason.
- **Your data carries over.** Memory banks are still read from `<game dir>/chesttracker/` and config
  from `<config dir>/chesttracker.json5` — both paths unchanged.

## What changed

Minecraft 26.x is the first fully unobfuscated release, and 1.21.9 replaced immediate-mode GUI
drawing with a deferred render-state model. Between 1.21.4 and 26.2 that meant rewriting the entire
GUI layer, the in-world renderer, and all input handling.

- Ported to Minecraft 26.2 (Fabric Loader 0.19.3, Fabric API 0.156.0, Java 25, Gradle 9.5.1)
- GUI rewritten onto the 26.x extract-render-state model
- In-world highlighting rewritten onto `SubmitNodeCollector`
- Where Is It and JackFredLib are no longer separate dependencies — the parts this mod used are
  built in, so there is one jar instead of three

## Highlight improvements over upstream

- Highlights **pulse** in size and opacity, so they are easier to spot
- Highlights are **translucent** by default rather than fully opaque, so the container stays visible
- Highlights last **12 seconds** instead of 5, holding full opacity before fading

## Removed

No 26.x builds exist upstream for these:

- **Litematica / MaLiLib** integration (material-list search buttons)
- **Expanded Storage** integration

## Known limitation

Highlights **do not show through walls**. The original disabled depth testing so containers hidden
behind terrain were still visible; 26.2 provides no equivalent render type out of the box, so this
needs a custom render pipeline and is not yet implemented.
